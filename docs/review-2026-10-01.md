# Public-card review — 2026-10-01

After discussing the existing Lyroo Research conversation in Grok Bot, verified
the public card endpoint spread stored GitHub data without a field allowlist.
The fix applies the same typed public contract on profile/share writes, legacy
public reads, and Telegram caption inputs. Public AI output has an independent
allowlist, including nested skills. Owner-only profile data remains owner-only.
Generated image responses contain image bytes and are unchanged.

Also added generic Open Graph metadata, root-only sitemap and robots endpoints
using APP_ORIGIN, gzip, immutable caching for Vite hashed JS/CSS, and explicit
404 responses for missing assets. Existing API no-store behavior is retained.
The sitemap deliberately does not enumerate accounts.

Personalized HTML/OG for shared cards requires a separate server-rendered shell
design; generic metadata does not implement this. No license changes or
deployment were performed.

## Deployment verification

Docker was not running locally, so nginx runtime validation remains necessary:

1. Validate the rebuilt frontend container with `nginx -t` before rollout.
2. Check robots.txt is text/plain and sitemap.xml is application/xml.
3. Verify an existing hashed asset has immutable caching, a missing asset is
   404 without immutable caching, HTML is no-cache, and gzip sets Vary.
4. Verify public card responses remain no-store and contain only the public
   contract. If an upstream cache previously overrode no-store, purge its old
   card responses. Changing origin headers cannot invalidate existing copies.

Old database snapshots are sanitized when served and replaced on the next
profile sync; this is not a destructive database cleanup or backup purge.
