**قوانین مالک (غیرقابل‌نقض در CORE):**
1. فقط **یک** نسل AI دوزبانه در هر ۲۴ ساعت یا تغییر عمده؛ تعویض زبان نسل جدید نمی‌سازد.
2. کارت اشتراک‌گذاری‌شده **همیشه عمومی**؛ گزارش و زمان **خصوصی**.
3. گالری/ایندکس **opt-in جدا** است؛ فلگ legacy `published` مجوز خاموش/روشن گالری نیست.
4. تلگرام: انتشار اول، سپس قانون ۷روز + سیاست عضویت ۲ ساعت.
5. بدون رتبه‌بندی عمومی افراد، بدون چت/کامنت اجتماعی در CORE.
6. بدون multi-shot AI، بدون پیش‌بینی burnout، بدون قیمت‌گذاری دلخواه در سند.

## ۲. تمایز محصول (۳ محور)

1. **کارت دوزبانهٔ زنده با AI منضبط** — یک نسل کنترل‌شده، نه چت بی‌پایان.  
2. **استودیوی شخصی** — گزارش و تایمر خصوصی؛ کارت همیشه عمومی.  
3. **تلگرام صادقانه** — وضعیت preview / OK / UNKNOWN + reconcile؛ نه «ارسال شد» دروغین.

## ۴. دروازهٔ تحویل فنی در برابر KPI محصول

### ۴.۱ Delivery gates (تیم / پذیرش اسپرینت)
- CI روی `main` سبز  
- تست fixture آلوده: صفر کلید حساس روی `/api/cards/<login>`  
- قرارداد AI و تلگرام در تست‌ها قفل  
- `/api/health` و کش HTML/assets مطابق توافق  

### ۴.۲ KPI محصول (baseline بعد از پایان W2؛ فعلاً unknown)
1. **Activation** —٪ کاربران جدید که کارت را کامل می‌کنند  
2. **First-value time** — زمان تا اولین اشتراک یا اولین ارزش ملموس  
3. **Week-4 return** — بازگشت در هفتهٔ ۴  
4. **Share conversion** —٪ از فعال‌ها که لینک عمومی را به اشتراک می‌گذارند  
5. **Cost per active user** — فرمول هزینه (بدون قیمت فروش):  
   `CPU/DB + (تعداد نسل AI موفق × هزینهٔ واحد مدل) / کاربران فعال در دوره`  
   سقف نسل همان یک‌بار/۲۴س یا تغییر عمده است.

## ۵. معیار پذیرش CORE (۱۰ مورد)

1. CI سبز (فرانت + بک).  
2. API عمومی فاقد کلیدهای حساس (رگرسیون fixture).  
3. یک نسل AI دوزبانه /۲۴س یا تغییر عمده؛ تعویض زبان بدون نسل جدید.  
4. کارت عمومی همیشه؛ گزارش و تایمر فقط مالک.  
5. ویرایشگر: لینک‌ها + ۳ پین × ۳ فیلد متنی + ۹ تم بدون رگرسیون.  
6. override دستی fa/en هرگز با AI بازنویسی نمی‌شود؛ original حفظ است.  
7. restore کارت فقط revision جدید می‌سازد؛ تاریخچه پاک نمی‌شود.  
8. اسنپ‌شات/روند/CSV + تایمر تگ‌دار + یک هدف هفتگی؛ بدون نوتیف.  
9. job progress + last-good؛ I/O خارج TX؛ کلیدهای idempotent.  
10. TG: preview/status؛ UNKNOWN قابل reconcile ادمین؛ بدون retry کور.

## ۷. قرارداد داده / migration / rollback

- **Versioned contracts:** `card_schema_version` روی payload عمومی و ترجیحات؛ مهاجرت خواندن برای رکوردهای قدیمی از طریق همان helper sanitize.  
- **Overrides:** فیلدهای `manual_fa` / `manual_en` جدا از `generated_*`؛ AI فقط `generated_*` را می‌نویسد.  
- **Revisions:** append-only؛ restore = کپی به head جدید.  
- **Pinned projects:** حداکثر ۳؛ هر کدام ۳ اسکالر متنی (بدون آپلود غنی).  
- **Jobs/outbox:** وضعیت‌های `pending|running|succeeded|failed|unknown`؛ انتقال UNKNOWN فقط با reconcile صریح.  
- **Feature flags / rollback:** پرچم برای editor پیشرفته، jobs async، TG preview؛ خاموش‌کردن flag بدون حذف داده.  
- **Telegram:** هرگز exactly-once ادعا نشود؛ ارسال دوباره فقط پس از reconcile وقتی وضعیت UNKNOWN و بدون `message_id` قطعی است.

## ۸. هزینه (فرمول، بدون قیمت فروش)

```
cost_period ≈ infra_fixed
  + ai_generations_succeeded × cost_per_generation
  + telegram_api_calls × cost_per_call   # اگر معنادار باشد
  + storage_growth × cost_per_gb
```

`cost_per_active_user = cost_period / active_users_period`  
کنترل اصلی هزینهٔ AI: سقف نسل مالک + idempotency jobs.
